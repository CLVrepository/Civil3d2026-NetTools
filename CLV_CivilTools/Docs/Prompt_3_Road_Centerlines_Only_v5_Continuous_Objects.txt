PROMPT 3 — ROAD CENTERLINES ONLY FROM PROMPT 1 / PROMPT 2 CONTROL, QA, AND CAD CSV

You are continuing a CAD reconstruction review of a recorded survey, parcel map, subdivision map, record of survey, final map, boundary map, or similar civil/survey PDF.

Prompt 1 has already created the sectional/control framework and anchored the user-marked POC/control point at:

POC / Control Anchor X = 10000.0000
POC / Control Anchor Y = 10000.0000

Prompt 2 has already created the exterior boundary from the resolved Prompt 1 framework. The user may have imported the Prompt 2 boundary into CAD, resolved it to 0.00 closure, and slightly moved/aligned it to match right-of-way/control linework.

This Prompt 3 is now CENTERLINE ONLY.

The user will highlight the road centerline path to build. Use the highlighted centerline path and the map labels to calculate road centerline linework only.

Do not build road edges.
Do not build right-of-way lines.
Do not build road common-element outlines.
Do not build offsets.
Do not build cul-de-sac edge circles/arcs.
Do not build curb returns or road edge returns.
Do not build lots, common elements, or easements.
Do not rebuild the sectional/control framework or exterior boundary.

The goal is to create a clean CAD-ready centerline CSV that imports only the road centerline geometry. Road offsets, cul-de-sacs, edge generation, and road-width tools will be handled later by a separate CAD script.

IMPORTANT COORDINATE RULE

The Prompt 1 POC/control anchor remains:

X = 10000.0000
Y = 10000.0000

Do not move the road centerline start point to 10000,10000 unless the highlighted road centerline actually begins at the Prompt 1 POC.

Use the Prompt 1 and Prompt 2 geometry as the coordinate framework. Work from the 10000,10000 POC/control anchor through the resolved control/boundary geometry to calculate the actual CAD coordinates of the highlighted road centerline.

The road centerline must be located by calculated ties, intersections, offsets, centerline labels, boundary relationships, and control relationships from Prompt 1 and Prompt 2. Do not scale, rotate, or visually shift centerlines to fit the PDF.

If the road centerline entry point or start point cannot be tied to the Prompt 1 / Prompt 2 framework, place the affected row on QA and report the missing tie.

CENTERLINE CHAIN-BUILD RULE

Build the highlighted road centerline with endpoint-to-endpoint chain logic.

* The first centerline row starts at the calculated centerline start point tied to the Prompt 1 / Prompt 2 framework.
* Each next row starts exactly at the previous centerline endpoint.
* Line endpoints are calculated from bearing and distance.
* Curve endpoints are calculated from the selected curve build method.
* Centerline intersection nodes must share the same coordinate.
* A branch centerline starts from the resolved parent centerline intersection node.
* Continue the parent road centerline through an intersection when the bearing/curve geometry does not change and the road name remains the same.
* Do not split the parent centerline into separate rows just because another road crosses or branches from it.
* Do not create disconnected loose centerline pieces unless the map shows separate roads and each has its own control tie.
* Do not trim or extend centerlines to road edges, since road edges are not being built in this prompt.
* Do not continue a centerline beyond the highlighted endpoint, intersection node, dead-end node, or cul-de-sac center point.

If a calculated endpoint does not match the expected map/control/intersection node, report the difference and place the row on QA unless the correction is supported by the source data.

CENTERLINE CONTINUITY / SINGLE-OBJECT EXPORT RULE

Before creating the final CSV, review the highlighted centerline chain by road name and merge adjacent same-geometry pieces into the longest valid continuous centerline object.

The goal is to avoid CAD imports that create many short line or curve pieces when the map shows one continuous road centerline.

For each road name:

* Keep separate road names as separate centerline chains.
* Do not break a centerline at crossings, lot lines, boundary intersections, road-width callouts, station points, tie points, annotation leaders, or minor construction nodes if the bearing and geometry continue through the point.
* Do not break a centerline at an intersection unless the road actually changes bearing, begins/ends, branches into a different road name, or the map identifies a true PI/PC/PT/curve transition.
* If two or more adjacent LINE rows share the same road name, same bearing, and are collinear with matching endpoints, merge them into one LINE row from the first start point to the last endpoint.
* If two or more adjacent CURVE rows share the same road name, same radius, same curve direction, same curve center/radial control, and are consecutive parts of one continuous curve, merge them into one CURVE row using the combined arc length and combined delta, unless the map labels them as separate curves.
* If a line continues through intermediate annotation points with the same bearing, use those intermediate points for QA only and do not create separate CSV rows for each sub-distance.
* Preserve all source labels and intermediate distances in Notes so the user can verify the map calls, but export the centerline as one continuous CAD object wherever the geometry is truly continuous.
* Only split a centerline when there is a true angle point, curve start, curve end, reverse curve, compound curve with a different radius, tangent-to-curve transition, road name change, or a real endpoint/dead-end/cul-de-sac center point.
* Do not split centerlines into boundary-to-boundary pieces at road crossings. Crossings and intersections are node references only unless they create a true geometry break.
* If intermediate map distances are shown along a longer continuous line, compare the sum of the sub-distances to the exported full line length and report the difference in QA.

Use these QA notes/status values when applicable:

* CENTERLINE_MERGED_CONTINUOUS_LINE
* CENTERLINE_MERGED_CONTINUOUS_CURVE
* INTERMEDIATE_POINT_USED_FOR_QA_ONLY
* ROAD_INTERSECTION_NOT_A_BREAK
* SAME_BEARING_SEGMENTS_MERGED
* CONTINUOUS_CURVE_SEGMENTS_MERGED
* CENTERLINE_SPLIT_AT_TRUE_ANGLE_POINT
* CENTERLINE_SPLIT_AT_PC_PT
* CENTERLINE_SPLIT_AT_ROAD_NAME_CHANGE
* CENTERLINE_NOT_MERGED_MANUAL_REVIEW

Do not mark a line as merged if the bearing changes beyond tolerance, the endpoints do not fall on the same line, the curve radius changes, the curve direction changes, or the road name changes.

Default merge tolerances unless I provide different values:

* Bearing match tolerance = 0°00'05".
* Collinearity / endpoint tolerance = 0.05 feet.
* Radius match tolerance = 0.05 feet.
* Arc/chord endpoint tolerance = 0.05 feet.

CENTERLINE INTERSECTION / BRANCH RULE

When one highlighted road centerline intersects or branches from another:

* Calculate the parent centerline first.
* Calculate the branch point as an actual coordinate on the parent centerline.
* The branch centerline must start exactly at the parent centerline node.
* If the branch is located by station/distance along the parent centerline, calculate that station from the resolved parent centerline.
* If the branch is located by intersection of two bearings, calculate the intersection from the resolved parent and branch geometry.
* If the branch point is only visually shown and not labeled, use the visual location only as QA and mark the affected row as APPROXIMATE or UNCERTAIN.

Do not start branch roads from visually guessed points if the map provides a calculable tie or intersection.

CENTERLINE CURVE RULES

For each centerline curve:

* Determine whether the curve belongs to the centerline. Do not use road-edge curve labels for centerline curves unless the map clearly states they are centerline curves or the centerline radius can be reliably derived.
* Identify LEFT or RIGHT relative to direction of centerline travel.
* Identify radius, delta, arc length, tangent, chord bearing, chord length, radial bearings, and radial IDs where shown.
* Build the curve from the best supported method:
  * TANGENT_CONTROLLED.
  * RADIAL_CONTROLLED.
  * CHORD_CONTROLLED.
  * COORDINATE_CONTROLLED.
  * UNKNOWN_CONTROL.
* Test shown radial and reversed radial when direction is ambiguous.
* Verify arc length, tangent, and chord math.
* Verify tangent continuity to adjacent centerline segments when the map implies a tangent curve.

If a curve label appears to belong to an edge/ROW line rather than the centerline, do not use it for centerline geometry unless the derivation is clear. Report CURVE_LABEL_NOT_CENTERLINE.

CUL-DE-SAC / DEAD-END CENTERLINE RULE

* If the centerline terminates at the center of a cul-de-sac, the final centerline endpoint should be the cul-de-sac center point.
* If the map shows the centerline ending at a PC/PT/tangent point instead of a circle center, use the mapped endpoint and report the endpoint basis.
* Do not draw the cul-de-sac edge radius, bulb circle, return curves, or offset edges in this Prompt 3.
* Record cul-de-sac radius and width information in Notes for future offset/cul-de-sac script development, but do not export edge geometry.

TIE LINE / OFFSET CLASSIFICATION RULE

A dotted, dashed, broken, or leader-style line with its own bearing and distance is a TIE_LINE or NON_OFFSET_TIE_LINE. Use it as a bearing-distance tie if it locates the centerline or control point. Do not treat it as a road width or perpendicular offset unless the map explicitly states it is an offset.

Classify labels as:

* CENTERLINE_CALL = bearing/distance/curve call directly on the highlighted centerline.
* CENTERLINE_TIE = bearing-distance tie to the centerline start, PI, PC, PT, intersection, or endpoint.
* CONTROL_TIE = bearing-distance tie from Prompt 1 / Prompt 2 control to a centerline point.
* OFFSET_DIMENSION = perpendicular offset used only if needed to locate centerline from resolved boundary/ROW/control.
* ROAD_WIDTH_OR_HALF_WIDTH = road width data for future offset script; do not create edges in this prompt.
* NON_OFFSET_TIE_LINE = dotted/dashed/leader bearing-distance tie, not a width.
* LOT_FRONTAGE_DISTANCE = lot frontage, not centerline geometry.
* AMBIGUOUS_CALLOUT = unclear; place affected geometry on QA.

Report any label that could be confused with an offset or frontage distance.
