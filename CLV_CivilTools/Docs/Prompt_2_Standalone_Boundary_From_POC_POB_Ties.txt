PROMPT 2 — STANDALONE BOUNDARY FROM POC / POB / TIE CALLS, QA, RADIAL CURVE REVIEW, AND CAD CSV
Version: 2026-07-09 Rev 1 - standalone boundary workflow, no Prompt 1 sectional dependency
Purpose: Create CAD-ready boundary linework from a recorded survey, parcel map, subdivision map, record of survey, final map, boundary map, or similar civil/survey PDF. This prompt starts from a POC/control anchor at 10000,10000, builds all commencement/tie lines to the POB, then builds the boundary from the POB using the map/legal calls. It produces a boundary CSV, an on-screen QA report, and a downloadable review report when file creation is available.

============================================================
CORE INTENT
============================================================
This prompt is for the project/site/parcel boundary only.

Do not build lots.
Do not build easements.
Do not build road centerline networks except as reference/tie rows needed to locate the boundary.
Do not build road edges, curb returns, ROW offsets, or cul-de-sac geometry unless the boundary itself is legally described along that feature.
Do not rebuild sectional/control linework from Prompt 1.
Do not require Prompt 1 geometry.
Prompt 1 is now only a review report and does not supply required CAD coordinates.
Prompt 4 has been removed from the workflow.

The goal is to create boundary geometry that can be imported into CAD and checked against a scaled PDF/image overlay.

============================================================
DEFAULT COORDINATE RULE
============================================================
Use X/Y coordinates in feet.

If no project/control coordinates are provided, place the Point of Commencement or controlling POC anchor at:

POC / Control Anchor X = 10000.0000
POC / Control Anchor Y = 10000.0000

Build the boundary in this order:

1. Identify the POC/control anchor.
2. Place the POC at 10000,10000 unless real project coordinates are provided.
3. Build all commencement/tie calls from the POC to the POB.
4. Calculate the POB coordinate from the tie sequence.
5. Build the boundary from the POB using the legal/map boundary calls.

Important:

* Do not assign the POB to 10000,10000 unless the POB is truly the same point as the POC.
* The POC is the commencement/control point.
* The POB is where the boundary begins.
* Commencement/tie lines are not boundary area lines.
* Boundary closure and area must use boundary calls only, not commencement/tie lines.

Coordinate conventions:

* Easting = X.
* Northing = Y.
* N theta E = +X, +Y.
* S theta E = +X, -Y.
* S theta W = -X, -Y.
* N theta W = -X, +Y.
* Export coordinates to at least 4 decimals, preferably 6 decimals.
* Do not round coordinates so aggressively that closure changes.

============================================================
NO AUTOCLOSURE / NO FORCE-CLOSURE DEFAULT
============================================================
Build the boundary from the source calls exactly as read.

Do not perform autoclosure, rubber-sheeting, rotation, scaling, best-fit adjustment, or forced endpoint closure unless the user specifically requests an autoclosure-adjusted boundary.

The required first geometry build is the SOURCE-CALL BUILD.

Report:

* Source-call closure delta X.
* Source-call closure delta Y.
* Source-call closure distance.
* Perimeter.
* Closure ratio, if possible.
* Likely source of error, if visible.

Do not force the final endpoint back to the POB merely to close the boundary.
If the boundary does not close, report the gap and mark the file QA or NOT READY as appropriate.

============================================================
MARKUP / COLOR PRIORITY RULE
============================================================
Use map/legal labels first, but user markup controls extraction priority.

Common markup meanings:

* Orange circle = POC/control anchor, normally placed at X=10000,Y=10000.
* Yellow highlight = boundary to reconstruct in this Prompt 2.
* Blue circle or blue arrow = possible POB, boundary start, or direction marker; does not move the POC coordinate.
* Pink highlight = roadway/control centerlines; reference only unless needed as a tie/control feature.
* Green highlight = ROW/road edge/private street edge/offset; reference only unless boundary is legally described along it.
* Purple highlight = old sectional/control reference; not required by this Prompt 2.

If yellow boundary highlight exists, follow the yellow boundary.
If no yellow highlight exists, identify the intended exterior/site boundary from the legal description, map labels, parcel lines, and user instructions.

* Recording number / document number.

* Owner / grantor / related party names, if relevant.
* County and state.
* PLSS location.
* Plat/book/page references.

* Units.
* Stated area.
* Point of Commencement description.
* Point of Beginning description.
* All commencement/tie calls.
* All boundary calls.
* Line table data.
* Curve table data.
* Radial table data.
* Detail/exhibit references.

If missing or unreadable, write UNKNOWN or UNREADABLE. Do not guess.

============================================================
POC / POB / COMMENCEMENT BUILD RULE
============================================================
Build the POC and all tie lines before the boundary.

POC/POB method options:

* POC_AT_10000_10000 = default POC placement.
* POC_FROM_PROJECT_COORDINATES = real coordinate values are provided.
* POB_EQUALS_POC = POB is the same point as POC.
* BEARING_DISTANCE_TIE_FROM_POC = POB calculated by tie call from POC.
* MULTIPLE_TIE_CALLS_FROM_POC = POB calculated by multiple commencement/tie calls.
* MONUMENT_TIE = POB calculated from monument/control tie.
* ROW_OR_CENTERLINE_TIE = POB calculated from ROW/centerline/control relationship visible on the map.
* INTERSECTION_DERIVED = POB calculated from intersection of reliable source lines.
* PDF_OVERLAY_ALIGNED_QA = visually aligned for QA only, not production import.
* UNKNOWN = POB cannot be reliably calculated.

Use IMPORT only when the POB is calculable from source data.
Use IMPORT_QA_LAYER or MANUAL_REVIEW when the POB is partially supported.
Use DO_NOT_IMPORT when the POB cannot be located without guessing.

============================================================
BOUNDARY EXTRACTION RULES
============================================================
Extract the boundary sequence using:

* Legal description calls.
* Visible map labels.
* Line tables.
* Curve tables.
* Radial tables.
* Detail views.
* Monument descriptions.
* POC/POB/tie calls.
* User highlighted boundary route.

For every boundary segment, extract:

* Segment ID.
* From point.
* To point.
* Bearing.
* Distance.
* Curve data, if curved.
* Radius, delta, arc length, tangent, chord bearing, chord length, radial bearings, if shown.
* Source sheet/detail/table.
* Source label.
* Corrected label if reversed or corrected.
* Confidence.

Do not invent missing bearings, distances, curve data, radial bearings, or endpoints.
If a label is unreadable, mark it UNCERTAIN.
If a bearing is shown opposite the direction of travel, report the source bearing and corrected CAD bearing.
If legal description and map labels conflict, report both values and identify which source controls the CSV.

============================================================
BOUNDARY CHAIN-BUILD RULE
============================================================
Build the boundary endpoint-to-endpoint from the calculated POB coordinate.

* First boundary row starts at the calculated POB.
* Each next row starts exactly at the previous endpoint.
* Line endpoints are calculated from bearing and distance.
* Curve endpoints are calculated from curve build method, radius, delta, radial data, chord data, and LEFT/RIGHT direction.
* Do not force closure.
* Do not visually shift, rotate, scale, or stretch geometry to fit the PDF.
* Report endpoint gaps, overlaps, sequence conflicts, and closure errors.

============================================================
CURVE / RADIAL RULES
============================================================
For each boundary curve:

* Identify curve ID.
* Identify direction of travel.
* Identify LEFT or RIGHT relative to travel.
* Identify radius, delta, arc length, tangent, chord bearing, chord length, start radial bearing, end radial bearing, and radial IDs where shown.
* Determine whether radial bearings appear center-to-curve-point or curve-point-to-center.
* Treat radial bearings as bidirectional unless the map clearly defines the direction.
* Test shown radial and reversed radial when direction is ambiguous.
* Test LEFT and RIGHT if curve direction is uncertain.
* Prefer RADIAL_CONTROLLED when a start radial is shown unless tangent control is clearly shown.
* Use tangent control only when legal description, exhibit, or table supports tangency.
* Use chord control as fallback/check when needed.
* Do not fabricate missing curve data.

CurveBuildMethod options:

* TANGENT_CONTROLLED
* RADIAL_CONTROLLED
* CHORD_CONTROLLED
* COORDINATE_CONTROLLED
* UNKNOWN_CONTROL

* UNKNOWN

============================================================
TIE-LINE / OFFSET / FRONTAGE CLASSIFICATION RULE
============================================================
Before using any distance as a centerline offset, ROW offset, road width, half-width, strip width, or perpendicular dimension, classify the source graphic and label.

A dotted, dashed, broken, or leader-style line with its own bearing and distance is a TIE_LINE or NON_OFFSET_TIE_LINE. Use it as a bearing-distance tie if it locates a point. Do not treat it as a perpendicular offset unless the map explicitly states it is an offset.

Classify labels as:

* BOUNDARY_CALL
* COMMENCEMENT_TIE
* CONTROL_TIE
* OFFSET_DIMENSION
* ROW_WIDTH_OR_HALF_WIDTH
* NON_OFFSET_TIE_LINE
* LOT_FRONTAGE_DISTANCE
* AMBIGUOUS_CALLOUT

Report any label that could be confused with an offset, frontage, or boundary call.

============================================================
OFFSET / CENTERLINE / ROW CONTROL VERIFICATION
============================================================
When the boundary is described relative to a centerline, ROW line, section line, offset, width, half-width, or tie, verify the relationship if calculable.

Do not use Prompt 1 sectional geometry as a required source. Use only the current map/document and Prompt 2 generated tie/boundary geometry.

Check:

* Boundary offset from roadway/control centerline.
* Boundary offset from ROW line.
* ROW full width or half width.
* Perpendicular offsets.
* Monument/control ties.
* Boundary intersections with control lines.
* Dotted/dashed bearing-distance ties as ties only, not offsets.

============================================================
FORWARD CLOSURE CHECK
============================================================
After building the boundary from source calls, compute:

* POB coordinate.
* Ending coordinate.
* Delta X.
* Delta Y.
* Linear closure error.
* Boundary perimeter.
* Closure ratio, if possible.
* Area, if boundary is close enough to compute and it is appropriate.

Do not include commencement/tie lines in area.
Do not force closure.
Report pass/warn/fail.

============================================================
REVERSE BOUNDARY BUILD QA
============================================================
Perform a reverse-build QA check using the final forward-built geometry that will be exported.

Reverse build is QA only. Do not adjust geometry from the reverse check.

Procedure:

1. Use the same POB coordinate as the reverse-build start and closure target.
2. Reverse the final boundary sequence.
3. For LINE rows, swap start/end and use reciprocal bearing.
4. For CURVE rows, swap PC/PT, reverse travel, flip LEFT/RIGHT, and test radial direction as needed.
5. Chain-build the reversed boundary endpoint-to-endpoint.
6. Compare reverse-built endpoints to matching forward-built points.
7. Compare reverse ending coordinate to original POB.

Reverse report table:

ReverseSegment,ForwardSegment,Type,ReverseFromPoint,ReverseToPoint,ReverseStartX,ReverseStartY,ReverseEndX,ReverseEndY,ExpectedForwardPoint,ExpectedX,ExpectedY,EndpointDeltaX,EndpointDeltaY,EndpointGap,ReverseBearingOrCurve,CurveDirectionUsed,RadialDirectionUsed,ReverseQAStatus,Severity,Resolution,Notes

============================================================
SCALED PDF / IMAGE OVERLAY QA
============================================================
Overlay is QA only.

If image/PDF tools are available, compare the calculated Prompt 2 boundary and tie geometry against the scaled PDF/image.

Verify:

* POC/tie/POB relationship appears correct.
* Boundary follows highlighted yellow route.
* Boundary does not accidentally follow lot, ROW, easement, or centerline features.
* Curves appear on the correct side.
* Boundary endpoints and corners align with intended map features.
* Any visible mismatch is reported.

Do not move, rotate, scale, stretch, or visually nudge the geometry to fit the PDF.

============================================================
FINAL RELIABILITY RATING
============================================================
At the end, rate the Prompt 2 boundary reconstruction as one of:

* RELIABLE_BOUNDARY_FROM_POC_POB_TIES
  POC is identified, POB is calculated from source tie/control data, boundary sequence connects, curve/radial QA passes, reverse-build QA passes, closure is acceptable or clearly reported, and import rows are reliable.

* PARTIALLY_RELIABLE_BOUNDARY_FROM_POC_POB_TIES
  Boundary is useful for CAD review/import, but some segments, offsets, curves, ties, or legal/map conflicts require QA/manual verification.

* NOT_RELIABLE_BOUNDARY_FROM_POC_POB_TIES
  Boundary cannot be imported without substantial manual correction, POB cannot be calculated, source calls are missing/unreadable, curve/radial conflicts are unresolved, reverse-build QA fails, or legal/map conflicts materially affect the geometry.

============================================================
FINAL IMPORTANT RULES
============================================================
* Prompt 2 is standalone.
* Prompt 2 does not require Prompt 1 CAD geometry.
* Prompt 1 is review only.
* Prompt 4 has been removed.
* Place POC at 10000,10000 unless real coordinates are provided.
* Build ties from POC to POB.
* Build boundary from POB.
* Do not put POB at 10000,10000 unless POB equals POC.
* Do not force closure unless specifically requested.
* Perform forward closure and reverse-build QA.
* Keep curve/radial review.
* Keep tie-line vs offset classification.
* Perform scaled PDF/image overlay as QA only.
* Report all discrepancies. Do not silently force geometry.
