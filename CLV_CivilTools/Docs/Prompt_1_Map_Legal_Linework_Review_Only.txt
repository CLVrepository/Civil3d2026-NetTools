PROMPT 1 — MAP / LEGAL / LINEWORK REVIEW ONLY — ON-SCREEN FINDINGS REPORT
Version: 2026-07-09 Rev 1 - replaces sectional/control construction prompt
Purpose: Review a recorded survey, parcel map, subdivision map, record of survey, final map, boundary map, easement exhibit, or similar civil/survey PDF before CAD reconstruction begins. This prompt does not create CAD linework. It identifies project information, map/legal call issues, linework risks, missing data, curve/radial concerns, POC/POB/tie information, and recommended next steps before running Prompt 2, Prompt 3, or Prompt Easement.

============================================================
CORE INTENT
============================================================
This is a review prompt only.

Do not build sectional/control linework.
Do not auto-close a parent frame.
Do not create split points.
Do not create PLSS point CSV files.
Do not create boundary, road, easement, lot, ROW, or sectional import CSV files.
Do not visually fit or trace CAD geometry.

The goal is to produce a clear on-screen review report that helps the drafter catch obvious errors before CAD reconstruction starts.

Use this prompt to answer these questions before drafting:

1. What is the map/document?
2. What sheets, details, legal descriptions, tables, and notes were reviewed?
3. Is there a legal description or boundary narrative?
4. Is there a clear POC and POB?
5. Are the commencement/tie calls readable?
6. Are the boundary calls readable and in order?
7. Do the map labels, legal description, line tables, curve tables, radial tables, and highlighted linework appear to agree?
8. Are any calls missing, unreadable, duplicated, reversed, or suspicious?
9. Are any dotted/dashed lines being confused with offsets?
10. Are any curve/radial labels ambiguous?
11. Does the map appear ready for Prompt 2, Prompt 3, or Prompt Easement?

============================================================
DEFAULT COORDINATE / ANCHOR REVIEW
============================================================
The standard CAD coordinate framework used by later prompts is:

POC / Control Anchor X = 10000.0000
POC / Control Anchor Y = 10000.0000

For Prompt 1, do not calculate final CAD geometry from this point. Only identify whether the map/document shows a usable POC, control point, monument, or commencement point that later prompts can place at 10000,10000.

If the orange circle marks a point, identify what it appears to represent:

* POC / Point of Commencement.
* POB / Point of Beginning.
* Section corner.
* Quarter corner.
* Monument.
* Road/control intersection.
* Boundary corner.
* Other control point.
* Unknown.

If the orange circle is missing, report that no user-marked POC/control anchor was found.

Important:

* The orange circle does not automatically mean the POB.
* The blue circle or blue arrow may mark a POB, start direction, or user note, but it does not move the standard POC coordinate.
* Prompt 2 will later decide how the POB is calculated from the POC and tie calls.

============================================================
MARKUP / COLOR REVIEW RULE
============================================================
Use map labels first, but user markup controls review priority.

Common markup meanings:

* Orange circle = likely POC/control anchor candidate.
* Yellow highlight = likely boundary to be built in Prompt 2.
* Pink highlight = likely road centerline to be built in Prompt 3.
* Green highlight = likely ROW, road edge, private street edge, offset, or reference line.
* Purple highlight = optional sectional/control reference only; Prompt 4 has been removed from this workflow.
* Blue circle/arrow = possible POB, start point, direction, or user note.

Prompt 1 must identify all highlighted colors present and explain what each appears to mean for later prompts.

============================================================
LEGAL DESCRIPTION REVIEW
============================================================
If the map/document includes a legal description, review it before any map call extraction.

Extract and report when readable:

* Recording number / document number.
* Map name / project name.
* APN / parcel number.
* Owner / grantor / party names, if relevant.
* County and state.
* PLSS location: section, township, range, meridian, aliquot parts.
* Plat/book/page or map recording references.
* Basis of bearing.
* Units.
* Stated area.
* Point of Commencement description.
* Point of Beginning description.
* Commencement/tie calls.
* Boundary calls.
* Curve table references.
* Radial table references.
* Exhibit or detail references.

If any item is missing or unreadable, report UNKNOWN or UNREADABLE. Do not guess.

Compare legal description and map linework at a review level only. Do not calculate full closure in Prompt 1 unless the user specifically asks for a rough check.

============================================================
BOUNDARY READINESS REVIEW
============================================================
Identify the intended Prompt 2 boundary.

Review:

* Whether yellow highlighted boundary exists.
* Whether the boundary sequence is clear.
* Whether the POB is labeled or marked.
* Whether there are tie calls from POC to POB.
* Whether the boundary can be built from bearings/distances/curves shown on the map or legal description.
* Whether line table and curve table labels are readable.
* Whether any boundary segment depends on a ROW, centerline, section line, monument, or external record not provided.
* Whether any boundary line appears to be a lot line, ROW line, centerline, easement, or adjacent parcel line instead of the intended project boundary.

Do not create the boundary. Only report whether Prompt 2 appears ready.

============================================================
ROAD CENTERLINE READINESS REVIEW
============================================================
Identify whether Prompt 3 can be run later.

Review:

* Whether pink highlighted centerline exists.
* Whether the road names are readable.
* Whether centerline bearings, distances, curve labels, and station/tie information are readable.
* Whether centerlines can be tied to the Prompt 2 boundary/POC framework.
* Whether road edge or ROW labels might be confused for centerline labels.
* Whether cul-de-sac/knuckle centerline endpoints are identifiable.

Do not build centerlines in Prompt 1.

============================================================
EASEMENT READINESS REVIEW
============================================================
If the document appears to include an easement, review whether Prompt Easement can be run later.

Review:

* Easement purpose.
* Grantee/easement holder.
* POC and POB descriptions.
* Commencement/tie calls.
* Easement boundary calls.
* Strip width or exact offset conditions.
* Parent line/curve used for offset or strip geometry.
* Stated area.
* Whether adjacent/existing easements might be confused with the easement to build.

Do not build the easement in Prompt 1.

============================================================
TIE-LINE / OFFSET / FRONTAGE CLASSIFICATION REVIEW
============================================================
Before later prompts use any distance as an offset, classify the label.

A dotted, dashed, broken, or leader-style line with its own bearing and distance is normally a TIE_LINE or NON_OFFSET_TIE_LINE, not a perpendicular offset.

Classify visible labels as:

* BOUNDARY_CALL = bearing/distance/curve call directly on the boundary.
* CENTERLINE_CALL = bearing/distance/curve call directly on a road centerline.
* COMMENCEMENT_TIE = bearing-distance call from POC/control point to POB or another control point.
* CONTROL_TIE = bearing-distance call from a monument/control point to another point.
* OFFSET_DIMENSION = perpendicular offset, usually shown normal to the controlling line and usually without a bearing.
* ROW_WIDTH_OR_HALF_WIDTH = explicit road width, ROW width, or half-width.
* STRIP_WIDTH = easement or corridor width.
* LOT_FRONTAGE_DISTANCE = frontage along lot/parcel line, not a tie or offset.
* NON_OFFSET_TIE_LINE = dotted/dashed/leader bearing-distance tie, not a width.
* AMBIGUOUS_CALLOUT = unclear and must be manually reviewed.

Report any label that could be confused with an offset, ROW width, frontage, or tie.

============================================================
CURVE / RADIAL REVIEW
============================================================
For every visible curve label that may affect a boundary, road centerline, or easement:

Identify when readable:

* Curve ID.
* Feature type: boundary, centerline, ROW/edge, easement, unknown.
* Direction of travel, if shown.
* LEFT or RIGHT direction, if determinable.
* Radius.
* Delta.
* Arc length.
* Tangent.
* Chord bearing.
* Chord length.
* Start radial bearing.
* End radial bearing.
* Radial table ID.
* Whether the curve appears tangent-controlled, radial-controlled, chord-controlled, or unknown.

Report warnings for:

* curve label may belong to nearby road edge/ROW rather than centerline/boundary;
* radial direction ambiguous;
* chord/arc/radius values missing;
* curve table label unreadable;
* likely reversed bearing or radial;
* legal/map/table conflict;
* curve data insufficient for CAD construction.

Do not invent missing curve data.

============================================================
SCALED PDF / IMAGE OVERLAY REVIEW
============================================================
Prompt 1 may comment on whether overlay QA will likely be useful later, but it does not create geometry to overlay.

Review whether the PDF/image appears suitable for overlay QA:

* Is the map sheet legible?
* Are scale and north arrow readable?
* Is the scan distorted, skewed, cropped, or blurry?
* Are tables legible enough for CAD extraction?
* Are highlighted routes visible?

Report overlay concerns that may affect Prompt 2/3/Easement.

============================================================
ON-SCREEN OUTPUT ONLY
============================================================
The default output for Prompt 1 is an on-screen report only.

Do not create files unless the user specifically asks for a downloadable report.
Do not create CSV files from Prompt 1.
Do not create CAD import rows from Prompt 1.

============================================================
FINAL IMPORTANT RULES
============================================================
* Prompt 1 is review only.
* Do not create CAD linework.
* Do not create CSV files unless the user specifically asks for a storage/export file.
* Do not calculate final coordinates except simple explanatory POC/POB review if clearly provided.
* Do not replace Prompt 2, Prompt 3, or Prompt Easement.
* Do not rely on OCR if the image is readable by visual review; use OCR only as a last resort.
* Report uncertainty clearly.
* Keep the on-screen report concise enough to review before drafting.
* Prompt 4 has been removed from the required workflow.
