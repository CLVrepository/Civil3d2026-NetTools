# Sewer manhole information starter

Current workflow: import/manual entry, place/refresh, then select an info block and destination structure. Pipe connections are matched automatically using START/END roles and available WCS compass directions, including endpoint tangents for curved pipes; review the completed preview and confirm. Apply now resolves pipe families/nominal sizes and same-family structure barrel sizes before editing. CLV-Non Anno remains required for new/refreshed block text.

## Purpose and scope

Import plan-extracted JSON or manually enter sewer manholes into a DWG catalog, place attributed info blocks, then transfer a reviewed block snapshot to one existing Civil 3D gravity structure and automatically matched connected pipe ends. The routine does not extract PDFs inside CAD. The separately prepared JSON is the input; unzip the extraction package first. CSV is a review report, not an import file.

Q1 > ADJUST > SEWER PLAN DATA > MANHOLE INFO opens the WinForms manager. Each manager invocation performs one action and ends, so native Undo applies to that action. No new PaletteSet or external block/LISP resource is required. Actual project framework remains net10.0-windows; it is unchanged.

| Command | Purpose |
|---|---|
| SSMHINFO | Catalog list, source/details viewer and action chooser. |
| SSMHIMPORT | Import/merge a JSON catalog after a count/name/rim/size preview. |
| SSMHADD | Add a manually entered manhole; initializes a project catalog if needed. |
| SSMHEDIT | Enter an existing manhole number, then edit its data. |
| SSMHINSERT | Enter a manhole number, pick marker XY and text height, place the info block. |
| SSMHREFRESH | Refresh one placed block from its current catalog record, after old/new preview. |
| SSMHAPPLY | Pick an info block and native structure; review automatic matches and apply data. |
| SSMHEXPORT | Export the current drawing catalog to JSON for reuse. |

## Catalog data

The naming convention is `{project}-SSMH-{number:02d}`: minimum two number digits, preserving the plan number; numbers above 99 are not truncated. Source IDs remain separate. Storm SDMH and drop inlets are outside this version. One project catalog per DWG is supported.

Accepted input schemas are `clv.sewer-manhole-catalog/0.1-draft`, `/0.2-draft` and `/1.0`. The reviewed extraction format is supported directly. Elevations must be feet and diameters inches. Unknown numbers remain JSON null/blank; measured zero and negative elevations remain valid. Positive sizes are required when supplied. Names, unique numbers, unique connection identities, finite values, invert below rim, supported schemas and maximum sizes are validated before database writes. Duplicate JSON keys, including case variants, are rejected. Import size limit is 8 MiB; maximum 10,000 manholes and 32 connections per manhole.

Records include rim, structure diameter and its basis/source wording, station, notes, source references and an arbitrary connection list. Each connection retains IN/OUT, direction, invert, pipe diameter, material code, physical material family, specification, raw material label, source metadata and optional neighboring manhole name. Material codes such as C900, PVC, RCP and SDR35 are supported as text; C-900 and SDR-35 normalize during manual entry. Apply maps supported material/specification codes to the exact CLV families described below; catalog IDs are resolved from the drawing's assigned parts list. Preserve BASE wording for structure size. Under the requested sewer workflow, the extracted base size selects the corresponding nominal inner/barrel size within the chosen manhole family; it is never used as frame/opening or outside diameter. Verify that interpretation against the selected catalog family in the preview.

Unknown source fields, sheet references, datum and extraction issues round-trip through JSON extension data. Source extraction notes remain historical when editing records; manual notes/review status distinguish subsequent edits. Import replaces matching manhole numbers only after confirmation, retains manual records absent from the file, and records the latest import metadata. Different projects or declared vertical datum names cannot be merged. No elevation/datum transformation is applied. Export includes manual changes.

## Drawing and block persistence

- Catalog: Named Objects Dictionary Xrecord `CLV_SEWER_CATALOG_V1`, JSON in short DXF text chunks. It travels with a saved DWG, rather than being a process-only cache.
- Layer: `CLV-SSMH-INFO`, green ACI 3/nonplot when newly created. Existing layer settings are preserved; an off/frozen/locked/dependent layer prevents placement. Current layer is not changed.
- Definitions: `CLV_SSMH_INFO_V1_Cnn`, generated once per connection count with a small circle/cross and standard attributes. Existing unrelated definitions with the same names are refused. New and refreshed attributes use the existing **CLV-Non Anno** text style. A missing style stops placement/refresh and asks the operator to load it from the CLV template; no fallback style is used. Existing tool-generated definition attributes are updated when reused; use SSMHREFRESH on an existing placed block to update its own attribute references.
- Block: marker uses the picked WCS XY at Z=0, regardless of picked Z/UCS. Rim and inverts are data, not block insertion elevation. Text height controls the uniform block scale. Attributes show the generated name, rim, structure size/basis, source ID/station and one line per pipe. Attribute grips can reposition text.
- Snapshot: block extension Xrecord `CLV_SEWER_INFO_BLOCK_V1` holds one complete catalog record plus project metadata. Copying the block preserves its snapshot. The snapshot is independent of later imports/edits; no reactive update changes an existing block silently.
- Direct ATTEDIT changes are not authoritative. Apply refuses changed/missing/duplicate visible attributes; edit the catalog and refresh instead. Refresh replaces attributes/snapshot and resets their positions, preserving block insertion/scale/rotation/layer. Existing erased attribute IDs are ignored on readback.
- If a drawing catalog has a changed matching record, Apply requires Refresh first. A valid copied block can also be used without a drawing catalog; the full snapshot is available for review.

## Network transfer

Use the Model tab, an editable local gravity structure and pipes, and Civil drawing units Feet. Data-reference/read-only parts and locked/dependent layers are refused. Pick the block and destination structure. There is no transfer-scope prompt. Name/rim are always included and AutomaticRimSurfaceAdjustment is disabled for the plan-controlled rim.

A known rim is required, but plan/native connection counts may differ. The routine automatically uses Mark's downstream drawing convention: a native START at the selected structure is OUT; a native END there is IN. For each role, available plan compass directions are compared with the WCS outward direction at the structure-side endpoint: the straight run direction, or the tangent pointing into the pipe's plan arc for a curved run. N/NE/E/SE/S/SW/W/NW and full-word/punctuated equivalents are recognized. Normal matching uses the 45-degree compass sector. A bounded fallback admits a discrepancy at or up to 5 degrees beyond that sector edge (at most 27.5 degrees from the plan compass center) only when the entire input contains exactly one native pipe and one plan connection for that IN/OUT role. Both directions and the selected invert must be known. Other same-role rows still count even if already matched, far away, missing a direction or missing an invert; the fallback never invents uniqueness by discarding them. Each fallback carries an explicit preview/audit/completion warning with the measured difference. Larger discrepancies and ambiguous boundary cases remain unresolved. A unique compatible role may match if direction is unavailable. Multiple candidates or two native pipes claiming one plan connection are unresolved, not chosen by order. Assigned inverts must be known. Missing plan connections remain pending and ambiguous native pipes remain unchanged, while name/rim and resolved endpoints can apply. No mapping dialog is shown.

This uses the stated START/END orientation convention, not current slopes (which may still be uninitialized). If a network was drawn with reversed start/end ordering, its roles must be corrected before relying on automatic matching. WCS XY compass matching is independent of the current UCS/view; no grid/true-north rotation is assumed. Direction conflicts or unrecognized/insufficient direction information for multiple same-role branches remain visible in the final preview. Pipes attached to the selected structure at both ends are refused when matched. Straight and curved circular gravity pipes are supported. Query Pipe.SubEntityType first. Only curved pipes read Pipe.CurveGeometry/GetArc2d/Bulge; straight pipes never request arc geometry. Curved-pipe matches use the local arc tangent at the selected endpoint, oriented into the run, independently of native/arc endpoint parameter ordering. Segmented/flex and noncircular pipe types remain outside this version.

Preview shows old/new name and rim, the automatic rim setting, plan structure size, current and target native families/sizes, each mapped START/END, current and desired invert, modeled inner height and plan material/specification, plus the full source record. The confirmation button remains disabled until the review acknowledgement is checked. Cancel/Esc aborts before writes.

Invert convention: apply the plan value at the CURRENT modeled pipe endpoint. Compute centerline Z as `plan invert + actual native InnerHeight / 2`, retaining endpoint XY and the opposite endpoint's INVERT. A material/size change can alter actual inner height, so both centerline Z values may move to preserve their respective inverts. Swaps happen first; nominal plan diameter is not substituted for the new part's actual inner height. There is NO assumed inner-wall/outer-wall/structure-center invert correction. If project callouts require such a correction, establish that convention before use; structure diameter is used only for same-family nominal barrel-size matching. The other endpoint may need a later transfer from its own manhole, so inspect final slopes/flow after applying both ends.

The preview lists matched changes, every pending plan connection and each unresolved existing pipe left unchanged, including why it could not be matched. Curved matches identify the local tangent and existing plan radius. All maps and changes for one structure are one transaction. Readback checks requested endpoint elevations, all network pipe XY, unchanged pipes' Z/heights/parts, mapped pipes' planned selected-end invert and retained opposite-end invert using the new native height, connectivity and exact target family/size IDs. Structure XY and family remain unchanged; selected size must equal the resolved target and frame diameter must be retained; adjacent structure name/rim/sump/automatic-rim properties are checked. The selected structure may natively adjust its sump as its connected inverts/rim change; the routine does not assign a sump elevation. A differing native result or collateral edit aborts the transaction. For a curved pipe, reconstruct its PipeCurveGeometry from the retained endpoint XY, original bulge and desired endpoint Z (the other endpoint invert is retained with the new inner height), then assign it back to the same native pipe. Post-write validation checks subtype, arc center/radius/endpoints, clockwise flag, sweep and bulge in addition to the existing endpoint/connectivity/part checks. Arc plan lengths use a 1e-6-foot tolerance; bulge/sweep use 1e-10; existing endpoint XYZ checks remain 1e-7. No ApplyRules call, structure/pipe creation or flattening/chording is performed. Native SwapPartFamilyAndSize preserves the existing part ObjectId; any unexpected network geometry/connectivity/adjacent-structure changes roll back the whole transaction.

The destination stores the reviewed plan record/source block handle/mapping in `CLV_SEWER_APPLIED_INFO_V1`. Mapped pipe ends store connection data separately in `CLV_SEWER_PLAN_START_V1` or `CLV_SEWER_PLAN_END_V1`, retaining the other end's metadata. The structure audit also stores pending connection IDs and existing pipe handles left unchanged, the START/END convention and per-pipe automatic-match evidence. The completion message reports actual verified native name/rim, applied endpoint count, pending plan connections and unchanged native pipes; it lists each pending connection. Structure/mapped pipe graphics are marked modified and the view regenerated after commit. The version-2 structure audit includes resolved structure/pipe part descriptions and actual post-swap inside heights.

## Automatic parts and sizes

Apply uses each matched connection's own plan data. A sequence of separate pipes may therefore use PVC, C900, then PVC even when the entire network was initially drawn using one default part. There is no global material choice and no per-pipe assignment table.

| Plan material/specification | Required pipe family |
|---|---|
| C900 / C-900 (including physical material PVC) | CLV_C900 |
| PVC / SDR35 / SDR-35 / ASTM D3034 | CLV_PVC |
| RCP | CLV_RCP |
| Missing material | Retain current family; resize if diameter is known. |

Resolve pipe families by exact case-insensitive name in the network's assigned parts list. Unknown nonblank materials and contradictory specifications stop before writes. Each nominal diameter must have a unique exact target size, or already be the current exact size. No closest-size substitution, substring family matching or catalog-definition creation is performed. Missing/ambiguous sizes report family, raw numeric diameter/units, converted inches, resolved nominal size and Material parameter. Do not add duplicate sizes merely because the old diagnostic said zero matches; inspect the reported data first. No missing definition is created automatically.

Pipe matching never parses the PartSize display name. Paired apostrophes, asterisks, spaces, misleading labels and custom display formatting cannot select or hide a size. Read PipeInnerDiameter from PartSize.SizeDataRecord and convert its explicit units to inches. Civil 3D has no standard nominal-diameter context. For supported CLV families, numeric definitions may use the nominal bore itself or the physical inside diameter in Shared/PipeCatalog. Enumerate both representations and require one supported nominal result within an absolute 0.01-inch rounding allowance. This is not a nearest-size search. Support is limited to nominal sizes in Shared/PipeCatalog and its recorded physical-ID variants; other sizes, non-CLV families or alternate C900 pressure-class IDs require an explicit mapping update, not a guessed match. If two part definitions qualify, keep the current compatible definition or refuse an ambiguous swap. Unknown units, dimensions outside the supported numeric mappings and invalid values remain unresolved; never substitute a display label. The preview identifies the numeric basis. A missing plan diameter keeps the current size when family is retained. For a family change without plan diameter, resolve the current nominal size from native InnerHeight (feet), not the name.

Read the optional Material parameter as a consistency check. Generic PVC is compatible with CLV_C900 and CLV_PVC because C900 is also PVC; exact configured family identity remains the specification key, preventing C900/SDR35 confusion. A nonblank unrecognized or conflicting Material value rejects that candidate and is shown in diagnostics. An absent Material parameter is explicitly reported and the exact family key is used. After swapping, native InnerHeight must agree with the selected numeric definition before any transfer can commit. Structure numeric barrel/frame matching and its stricter tolerance remain unchanged.

Structure type/family is retained. A supplied plan base/barrel size must match the family's StructInnerDiameter and the current structure FrameDiameter must match StructFrameDiameter on the target definition. Dimensions use their declared catalog units and 0.0001-inch matching tolerance. Frame size is checked again on the native structure after the swap. Missing/ambiguous barrel/frame metadata stops with diagnostics rather than selecting the first variant. Missing plan structure size leaves its part unchanged. An unsupported explicit diameter basis (for example an outside or opening diameter) stops rather than interpreting it as a barrel.

Before swapping, previously applied opposite-end metadata is checked for conflicting material/nominal diameter on the same native pipe. Revised current-catalog values take precedence when available, so correcting a record is possible without stale endpoint snapshots permanently blocking each other. Separate successive pipes can use different materials; one native pipe must have consistent material/nominal diameter at both ends. Missing opposite-end fields do not invent constraints. Different-project metadata is refused.

Native structure/pipe swaps occur in the same transaction before endpoint elevations are applied. The matched endpoint receives the plan invert using NEW actual InnerHeight; the opposite endpoint retains its previous invert using that same new height. Plan geometry and connections are validated before commit. The final preview shows the current-to-target parts, and cancellation/failure leaves all parts/data unchanged.

## Workstation acceptance on a drawing copy

1. Rebuild the full solution with Civil closed; verify the deployed stable DLL and fresh randomized DLL SHA256 match. Restart using the existing loader for `C:\Temp\C3DDev\CLV_CivilTools.dll`; do not NETLOAD a second DLL copy.
2. Import the extracted JSON. Check record counts, multiple IN rows, base sizes and material/specification fields, source metadata and blank incomplete records. Test Cancel at import and reimport a matching record while retaining an extra manually entered record.
3. Add a test record manually (including zero/negative invert values if appropriate), save, export/reimport and save/reopen the DWG. Check source/units/name and all dimensions remain separate.
4. Place records with 0, 2 and 3 connections; test a rotated UCS, text height, attribute grips, save/reopen, COPY and WBLOCK into a copy drawing. Marker XY should be WCS-correct and marker Z zero. Inspect info-layer settings and nonplot behavior. Verify CLV-Non Anno on each new attribute and after refreshing an old Standard-style block. In a test drawing missing that style, placement/refresh must fail without creating objects or changing source data.
5. Edit a record. Apply must refuse its stale placed block; Refresh must show old/new, retain block transform, reset attributes, and work again after changing the connection count. Test repeated refresh and direct ATTEDIT refusal.
6. Build a representative native network, including a multi-IN structure. Apply by picking only the info block and structure; it must proceed directly to a preview of automatic matches. Inspect actual Civil structure/pipe Properties and native labels, not only the generated block. Verify requested rim, native START/END invert convention, retained XY/opposite-end inverts and final slopes after both manholes are updated.
7. Reproduce the reported two-plan/one-native MH 01 case: the single outgoing START pipe toward N must automatically match OUT N; verify name/rim and its invert update while the incoming S stub stays pending. Test END incoming, multiple incoming NW/SW branches, unique role without a direction, conflicting directions, same-role/direction duplicates, zero native pipes, and unknown pending inverts. Test rotated UCS/view and confirm WCS matching remains stable. Straight pipes must reach the preview without the former SubEntityType/Curve2d exception. Reproduce the subsequent curved-pipe restriction at structures 2/3: curved pipes must now reach the automatic preview and update requested inverts on the same native objects. Inspect Properties and plan geometry before/after for radius, bulge, arc side, endpoints and connectivity. Test clockwise/counterclockwise, START/END, a mixed straight/curved structure, applying the opposite end later, and Undo/Redo. Test Auto Rim True -> False, duplicate destination names, missing rim, locked layers, DREFs and unsupported segmented/flex/noncircular matched pipes. Cancellation/failure must leave the network unchanged.
8. Draw a default-material network with successive PVC / C900 / PVC plan runs; apply at both ends and verify each pipe's native family, nominal size, actual ID and both inverts. Reapply to prove idempotence. Include 48/60/72-inch manholes in one family, retaining frame/opening diameter, and curved pipes during swaps. Test missing material/diameter, missing families/sizes, duplicate variants, unknown units, inconsistent opposite-end records and corrected catalog records. No closest-size or first-family selection is allowed. Verify same native ObjectIds/labels, save/reopen and Undo/Redo.
9. Test native minimum-cover/rim/sump constraints; refusal must roll back all edits/metadata. Test Undo and Redo for import, manual edit, placement, refresh and transfer. Check unrelated network geometry and applied metadata.

Host-independent tests also cover PVC/C900/RCP aliases and conflicts, nominal versus actual ID, explicit units, refusal of nearest sizes, opposite-end plan conflicts and invert preservation in PVC-to-C900-to-PVC changes. Host-independent tests include clockwise/counterclockwise outward endpoint tangents, scaled radius vectors, tangent-versus-chord connection choices and invalid radius vectors, as well as automatic roles, all eight WCS compass sectors, alias normalization, 360-degree wraparound, missing branches, duplicate claims, direction conflicts, unknown inverts, strict sector matching and guarded unique-role boundary fallback. Host-independent tests: `dotnet run --project Tests/SewerInfo.Tests/SewerInfo.Tests.csproj`. An optional JSON path after `--` tests the supplied extraction file through the actual parser and serialization round trip. These tests do not execute Autodesk code or validate live transaction/geometry behavior.

Full-solution build and live Civil 3D acceptance remain workstation tasks. Targeted source compilation and actual parser regressions are recorded separately in the release handoff.

- Reported case: Pipe DD218 requested nominal 8 in CLV_C900 but Apply returned zero matches while listing `8 '' C900`; the existing manual swap succeeded. The old label parser did not recognize that display format, and its fallback only accepted exact physical-ID table values. The custom drawing's numeric values have not been inspected here.
- On a drawing copy, retest the same source block/destination structure. The preview must show PipeInnerDiameter, units, resolved nominal diameter and Material for the 8-inch C900 target. Check the actual part ID/family in Properties after confirmation.
- Repeat C900 to PVC to C900, with two successive structures and any curved pipe. Check endpoint inverts, opposite-end invert, final slopes, connections, curve plan geometry and structure frame/barrel. Then test Cancel and Undo/Redo.
- Exercise a display name containing two apostrophes, spaced symbols or a deliberately different number. Numeric data must determine selection. Duplicate compatible definitions must not be chosen by order; conflicting material or unknown units must stop before edits and report raw metadata.
- Executable host-independent regressions and targeted Civil 3D-reference compilation are available in the task workspace. These do not replace a full solution build or live Civil 3D acceptance.


## Bounded compass-boundary matching regression and retest (2026-11-10)

- On a drawing copy, run SSMHAPPLY on the same block and structure. Review DIRECTION FALLBACK WARNINGS and the outgoing AUTO MATCH warning, expected OUT NE / 16-inch C900 / invert 3689.75 ft. Cancel if the physical connection is not the intended one. The completion log should show the applied direction warning and no pending/unresolved outgoing row.

Check incoming invert, opposite-end invert, slope, curve radius/bulge/side, endpoint XY, connectivity and adjacent structures. Reapply, then test Cancel, Undo and Redo. - Test exact sector edge, 27.5-degree limit, beyond-limit and opposing directions, multiple same-role rows, unknown invert and direction, both START/END roles, both curve orientations and rotated UCS/view.
